# 4. INT4로 줄이고 채점

3번의 BF16 LoRA 모델을 TorchAO INT4로 두 가지 방법(PTQ, QAT)으로 줄입니다. 그다음 네 모델(튜닝 전, BF16 LoRA, INT4 PTQ, INT4 QAT)을 2022~2024년 3,009문항으로 **모델마다 한 번만** 채점하고, 같은 문항끼리 비교합니다.

| 필요한 것 | 걸린 시간 (H100 NVL) | 결과 문서 |
|---|---|---|
| [3번](03_finetune.md)의 BF16 LoRA 모델 | QAT 학습 102분(600 step). 채점은 BF16 약 40초, INT4 약 6분(모델 읽기 포함) | [2. INT4 양자화](../talk/02_int4_quantization.md) |

## 순서

```bash
bash scripts/gpu/stage.sh b          # INT4 PTQ: 학습한 BF16 모델을 그대로 INT4로 변환 (약 7.2 GiB)
bash scripts/gpu/stage.sh c_smoke    # INT4 QAT: 5 step 시험 학습
bash scripts/gpu/stage.sh c          # INT4 QAT: 본학습 600 step 후 INT4로 저장

bash scripts/gpu/stage.sh final_base # 2022~2024년 문제, 모델마다 한 번
BACKEND=hf bash scripts/gpu/stage.sh final_A
bash scripts/gpu/stage.sh final_B
bash scripts/gpu/stage.sh final_C
bash scripts/gpu/stage.sh compare    # 같은 문항끼리 McNemar 비교 4쌍
```

- INT4 방식은 weight-only, group 128, tile-packed 형식 하나입니다(설정의 `quant:`).
- `final_*`은 같은 결과 파일이 있으면 다시 재지 않고 멈춥니다. 2022~2024년 문제는 마지막에 한 번만 보는 문제라서입니다.

### QAT 메모리

| GPU | 설정 | 메모 |
|---|---|---|
| H100 NVL 94GB | `--qat-batch 4 --qat-accum 4` (기본값) | 학습 중 73.3 GiB(`nvidia-smi`, 85 step 무렵 한 번 읽은 값) |
| 80GB급 | `--qat-batch 2 --qat-accum 8` | 한 step에 16문항인 것은 같습니다. 이 설정은 실측하지 않았습니다 |

## 확인

| 단계 | 파일 (`quantization/results/kormedmcqa_midm/`) | 볼 것 |
|---|---|---|
| `b` | `B_build_seed42.json` | `device`가 그 GPU. 폴더 크기 약 7.2 GiB(`du -sh quantization/artifacts/kormedmcqa_midm/B_int4_ptq_seed42`) |
| `c` | `C_train_seed42.json` | `global_step` 600, `train_seconds` |
| `final_*` | `eval_vllm_<모델>_seed42_h100.json` | `n_eval` 3,009, `n_unparsed` 0에 가까움, `accuracy` |
| `compare` | `compare_final_seed42_h100.json` | 쌍마다 한쪽만 맞힌 문항 수와 McNemar p |

이번 실행의 값은 [2번 결과 문서](../talk/02_int4_quantization.md)의 표에 있습니다. 같은 조건으로 다시 재서 같은 값이 나오는지는 확인하지 않았습니다.

## 다른 GPU에서 채점하기

INT4 파일은 torchao 텐서를 pickle(`.bin`)로 저장한 것이라, 만든 torch·torchao 빌드에 묶여 있습니다. 그래서 다른 GPU로는 BF16 safetensors 두 개만 옮기고 INT4는 그 GPU에서 다시 만듭니다.

1. BF16 LoRA 병합본을 `quantization/artifacts/kormedmcqa_midm/A_bf16_seed42/`에 둡니다.
2. QAT 학습이 끝난 BF16 가중치를 `quantization/artifacts/kormedmcqa_midm/C_int4_qat_seed42_bf16adapt/`에 둡니다. 공개 모델을 받으려면 `bash scripts/gpu/stage.sh fetch_hf`를 씁니다.
3. `stage.sh b`와 `stage.sh c_export`로 INT4를 다시 만듭니다. `B_build_seed42.json`, `C_export_seed42.json`의 `device`가 그 GPU인지 확인합니다.
4. `final_*`, `compare`와 [5번](05_serving.md)을 돌립니다. 결과 파일 이름에 GPU 종류(`_h100`, `_a100`)가 붙어 표를 GPU별로 따로 만듭니다.

## 학습한 가중치 공개 (선택)

```bash
python -m quantization.publish_hf --kind A_bf16 --dir <BF16 LoRA 병합 폴더> --repo <계정>/<레포> --train-json <학습 결과 JSON> --dry-run
```

- **먼저 `--dry-run`으로 모델 카드를 확인합니다.** 카드에는 데이터 출처, 비상업 조건, Mi:dm MIT 고지, "의료 조언 아님"이 들어갑니다.
- **올라가는 파일:** safetensors만 올라갑니다. INT4 pickle과 학습 상태 파일은 올리지 않습니다.
- **HF 토큰:** 그 레포에만 쓰기 권한이 있는 fine-grained 토큰을 쓰고, 업로드가 끝나면 폐기합니다. 토큰은 직접 `hf auth login`으로 넣고 스크립트에 적지 않습니다.

## 안 될 때

- **QAT에서 메모리 부족:** 위 「QAT 메모리」 표의 80GB 설정으로 낮춥니다.
- **`final_*`이 바로 멈춤:** 그 모델의 2022~2024년 결과 파일이 이미 있습니다. 정말 잘못 잰 경우에만 파일을 옮기고 다시 돌립니다.
- **QAT 학습이 끝난 뒤 스크립트가 깨짐:** 도는 중에 스크립트 파일을 덮어쓴 경우입니다([8번 문서](08_troubleshooting.md)). `stage.sh c_export`로 저장만 다시 합니다.
